Итоговая работа по курсу "Основы криптографии"

Вопрос 1. Трехсторонний протокол распределения ключей с использованием третьей стороны
Описание протокола секретной связи на основе симметричной криптосистемы с привлечением центра генерации и распределения ключей (ЦГРК). Роли сторон: отправитель (Алиса), получатель (Боб) и доверенная третья сторона — ЦГРК.
Основные этапы протокола:
1. Алиса и Боб заранее договариваются об используемом семействе симметричных шифров и устанавливают долговременные секретные ключи с ЦГРК.
2. ЦГРК генерирует сеансовый ключ k, который будет использоваться только для текущей сессии связи.
3. ЦГРК надежно передает сеансовый ключ k Алисе (например, шифруя его долговременным ключом, общим только между Алисой и ЦГРК).
4. Алиса пересылает зашифрованный сеансовый ключ Бобу по открытому каналу связи.
5. Алиса шифрует открытый текст x сеансовым ключом k, получая криптограмму y = E_k(x), и отправляет ее Бобу.
6. Боб расшифровывает криптограмму с помощью того же сеансового ключа k, восстанавливая исходное сообщение x = E_k^{-1}(y).
Итоговый результат: между Алисой и Бобом устанавливается общий секретный сеансовый ключ k, который используется для конфиденциальной связи, при этом распределение ключа осуществляется безопасно благодаря доверенному посреднику (ЦГРК). Сеансовый ключ хранится только в оперативной памяти и уничтожается после завершения сессии.

Вопрос 2. Формальные модели шифров
Криптографическая система (шифр) формально определяется как семейство отображений E = {E_k}_{k∈K}, где K — конечное множество допустимых значений ключа. 
Шифр E рассматривается как отображение X* × K → Y*, биективное по первой переменной, где X* — множество открытых текстов, а Y* — множество шифрованных текстов (криптограмм).
Зашифрование: y = E_k(x), где x ∈ X*, k ∈ K.
Расшифрование: x = D_k(y) = E_k^{-1}(y), где D — семейство обратных отображений.
Для поточных шифров модель строится на основе генератора гаммы: ключ k инициализирует детерминированный генератор псевдослучайных последовательностей, формирующий гамму z = (z_1, z_2, ...). Шифрование выполняется побитово через операцию XOR: y_i = x_i ⊕ z_i.
Для блочных шифров модель оперирует блоками фиксированной длины n: на вход подается блок открытого текста, на выходе — блок шифртекста той же длины. Для обработки сообщений произвольной длины применяются режимы работы (ECB, CBC, CFB, OFB и др.), которые связывают блоки через векторы инициализации или обратную связь.

Вопрос 3. Принципы построения поточных систем шифрования
Поточные шифры преобразуют данные побитово или побайтово, опираясь на следующие принципы:
1. Принцип генерации гаммы: короткий симметричный ключ преобразуется в длинную псевдослучайную последовательность (гамму), совпадающую по длине с открытым текстом. Гамма накладывается на текст операцией XOR. Ключ должен быть истинно случайным или криптографически стойким псевдослучайным, а его повторное использование недопустимо без смены вектора инициализации.
2. Принцип отсутствия распространения ошибок: поскольку шифрование выполняется побитово, однобитовая ошибка передачи в канале связи приводит только к однобитовой ошибке в расшифрованном тексте. Это делает поточные шифры эффективными для каналов с высоким уровнем шума (например, мобильная связь).
3. Принцип синхронизации: отправитель и получатель должны точно синхронизировать генераторы гаммы. При потере синхронизации требуется пересчет гаммы с нового ключа или использование самосинхронизирующихся схем, где гамма зависит от нескольких предыдущих блоков шифртекста.
4. Принцип вычислительной эффективности: операции поточных шифров просты (преимущественно XOR и сдвиги), что позволяет достигать высоких скоростей шифрования и легко реализовывать их как в программном, так и в аппаратном обеспечении.

Вопрос 4. Пример режима шифрования, в котором биективность не требуется
Примером является режим обратной связи по шифртексту (CFB — Cipher Feedback).
Обоснование: В режиме CFB блочный шифр используется не для непосредственного отображения блока открытого текста в блок шифртекста, а как генератор псевдослучайной гаммы. На каждом шаге алгоритм шифрования E_k применяется к предыдущему блоку шифртекста (или вектору инициализации), чтобы получить блок гаммы. Этот блок гаммы затем комбинируется с текущим блоком открытого текста операцией XOR для получения шифртекста.
Для расшифрования используется та же самая функция E_k, которая применяется к тем же самым входным блокам шифртекста, восстанавливая ту же самую гамму. Таким образом, для корректной работы режима CFB требуется только детерминированность и воспроизводимость выходных данных функции E_k. Биективность (однозначная обратимость) самого блочного отображения E_k не является строго необходимой, так как обратное отображение в режиме CFB не вызывается. Достаточно, чтобы генератор гаммы выдавал предсказуемую последовательность при одинаковых входных данных.

Вопрос 5. Расчет искажений блоков в режиме CFB
Дано: размер блока блочного шифра N = 64 бита, размер обратной связи s = 8 бит, в шифртексте исказился 1 бит.
Логика работы CFB: шифртекст C_i = P_i ⊕ MSB_s(E_k(C_{i-1})). При расшифровании: P_i = C_i ⊕ MSB_s(E_k(C_{i-1})).
Шаг 1: Искажение 1 бита в блоке шифртекста C_i напрямую приводит к искажению ровно 1 бита в соответствующем блоке открытого текста P_i (так как применяется операция XOR).
Шаг 2: Блок C_i с ошибкой подается на вход регистра сдвига для генерации гаммы следующего блока. Ошибка попадает в входные данные блочного шифра при вычислении гаммы для C_{i+1}.
Шаг 3: Поскольку размер обратной связи составляет 8 бит, а размер блока 64 бита, ошибка будет сдвигаться в регистре до полного выхода. Количество шагов, на которое распространится ошибка, равно N / s = 64 / 8 = 8.
Шаг 4: Таким образом, искаженная гамма будет сформирована для блоков с i-го по (i+7)-й включительно. Каждый из этих 8 блоков шифртекста будет расшифрован с использованием неверной гаммы, что приведет к искажению 1 бита в каждом соответствующем блоке открытого текста.
Ответ: Искажается 8 блоков открытого текста.

Вопрос 6. Расчет размера выхода хэш-функции для заданной вероятности коллизии
Используем вероятностную модель "парадокса дней рождений". Вероятность того, что среди n случайно выбранных сообщений хотя бы одна пара будет иметь одинаковое хэш-значение (коллизию), оценивается формулой:
P ≈ n² / 2^(n+1)
По условию требуется, чтобы вероятность не превышала 10^-9:
n² / 2^(n+1) ≤ 10^-9
Проведем подбор n с промежуточными вычислениями:
При n = 30: 30² / 2^31 = 900 / 2 147 483 648 ≈ 4,19 × 10^-7 (слишком велико)
При n = 35: 35² / 2^36 = 1225 / 68 719 476 736 ≈ 1,78 × 10^-8 (все еще больше 10^-9)
При n = 38: 38² / 2^39 = 1444 / 549 755 813 888 ≈ 2,63 × 10^-9 (близко, но все еще превышает)
При n = 39: 39² / 2^40 = 1521 / 1 099 511 627 776 ≈ 1,38 × 10^-9 (почти на границе)
При n = 40: 40² / 2^41 = 1600 / 2 199 023 255 552 ≈ 7,28 × 10^-10 (меньше 10^-9)
Таким образом, при n = 40 вероятность случайной коллизии среди всех возможных пар сообщений из выборки размером n впервые опускается ниже заданного порога 10^-9.
Ответ: n = 40 бит.
